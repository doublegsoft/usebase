基于 ModelBase DSL 设计的智能知识库生命周期

场景 1：发布知识文章 (Publish Article)

控制知识质量，确保只有经过审核的信息才能进入全公司的搜索池或投入给 AI (RAG) 训练。

实现“场景找知识”。将非结构化文本（如SOP手册）与结构化资产（如设备、工单）通过多态关系绑定。

场景 3：提交反馈与知识自愈 (Smart Feedback & Auto-Healing)

这是现代知识管理的核心。通过闭环反馈，自动下架过期知识，防止 AI/员工 被错误信息误导。

graph TD Start([开始: 提交知识评价
参数: article_id, score, comment]) --> Check1{文章存在
且评分在 1~5 之间?} Check1 -- 否 --> Err1[🚫 拦截: 参数非法] Check1 -- 是 --> Check2{用户是否
已评价过该文?} Check2 -- 是 --> Err2[🚫 拦截: 防刷机制, 您已评价过] Check2 -- 否 --> Insert[➕ 插入: 记录用户打分与建议] Insert --> Condition1{智能分支:
本次评分 <= 2分 ?} Condition1 -- 否 (好评/中评) --> End1([✅ 结束: 评价成功]) Condition1 -- 是 (差评) --> Calc[🧮 聚合计算: 获取该文章
最近 5 次的平均分] Calc --> Condition2{平均分 < 3.0分 ?} Condition2 -- 否 --> End1 Condition2 -- 是 (触发自愈) --> Mutate[🔄 变更: 文章状态降级
